# V3.0.0：看得见、可单步执行的 Agent / Skill / MCP 流程

## 1. 如何使用

更新并启动（先在旧服务终端按 Ctrl+C）：

```powershell
cd C:\AI-Study\Test-Agent-Skill-MCP
git pull --ff-only
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe web.py
```

浏览器打开 `http://127.0.0.1:8000`，刷新页面。

1. 勾选 **显示流程图 · 单步调试**。默认不勾选，不占用页面空间。
2. 输入原文，选择原文语言、需要的对照组合。免费模式仍无需模型和 Key。
3. 点击 **开始对照翻译**，程序停在第一个关键步骤前。
4. 在右侧点击 **下一步**，只放行当前步骤，直到下一处检查点。
5. 查看节点上的 Agent / Skill / MCP / Engine 类型、组合、状态及代码位置。
6. 代码区高亮本步骤下一条操作的起始行；Skill 节点还可以展开指令原文。
7. 最后放行“交付本组结果”，左侧显示译文；如果选中多组，会继续处理下一组。

**结束调试**会停止后续本地执行；取消“显示流程图”也会结束正在进行的调试并隐藏面板。已发送到远程翻译服务或模型的请求不能撤回，可能已产生用量。已完成的组合结果会保留。

桌面页面中流程图显示在右侧。较窄桌面视口会将译文卡片纵向排列，手机宽度下调试面板放在上方，方便点击下一步。

## 2. 图中的角色怎样理解

| 类型 | 含义 | 本项目示例 |
|---|---|---|
| Agent | 推进任务的编排程序；大模型模式中还处理模型决策和工具循环 | 选择路径、检查模型输出、回传工具结果、交付译文 |
| Skill | 从文件读取可复用的翻译规则 | 加载 `skills/zh-en/SKILL.md` 和共享规则 |
| MCP | 客户端与工具服务之间的真实协议通信 | 启动子进程、初始化会话、发现工具、查询词表 |
| Engine | 免费翻译服务的执行步骤 | 向 MyMemory 发送一个待翻译分句 |

免费模式中的“Agent”表示确定性的编排程序，不表示大模型推理。免费模式虽然会读取所选 Skill 文件，但翻译引擎不会解释或执行这些模型指令；模型模式才会把 Skill 放入模型上下文。页面和步骤说明会明确区分。

## 3. 免费模式示例

选择英文原文 `Hello!`，只勾选中英对照。流程为：

```text
Agent：安排本组翻译
  ↓
Skill：读取中英组合规则
  ↓
Engine：请求英文 → 中文免费翻译
  ↓
Agent：英文栏保留原文，不发送翻译请求
  ↓
MCP：启动 Python 工具服务子进程
  ↓
MCP：初始化 stdio 会话
  ↓
MCP：调用 lookup_term 查询本地术语
  ↓
Agent：整理词义与用法
  ↓
Agent：交付本组结果
```

每一处都是实际程序到达的检查点。多句原文可能产生多个 Engine 节点；第三语言输入可能需要两种目标语言请求。节点数量来自真实运行，不是固定播放的动画。

## 4. 大模型模式示例

```text
Agent：安排组合
  → Skill：加载对应技能
  → MCP：启动、初始化、发现工具
  → Agent：请求模型（发送 Skill + 工具定义）
  → Agent：检查模型返回
  → MCP：执行模型要求的术语查询
  → Agent：回传 function_call_output
  → Agent：再次请求模型
  → Agent：校验结构化译文
  → Agent：交付结果
```

模型可以继续要求查询，所以这条路径可能重复。每个模型请求之前都会暂停；放行该步骤可能产生 API 用量。不会展示模型隐藏推理，仅展示程序实际调用与处理步骤。

## 5. 代码结构

```text
debug_trace.py          # ContextVar 调试上下文、源代码定位、异步门控、会话生命周期
web.py                 # 调试会话 HTTP 接口及逐组任务编排
static/debug.js        # 状态轮询、流程图、代码行展示、下一步/取消
static/debug.css       # 右侧流程节点和代码面板样式
tests/test_debug.py    # 真正暂停、放行、取消、MCP 和 SDK 调用验证
```

`agent.py`、`comparison.py`、`free_translation.py`、`mcp_bridge.py` 的关键调用前增加：

```python
await step("MCP", "初始化 MCP 会话", "Client 与 Server 完成协议握手。")
await session.initialize()
```

没有调试上下文时，`step()` 立即返回，原有 API、CLI 和普通翻译流程继续运行。

调试上下文存在时：

1. `inspect.currentframe().f_back` 取得当前检查点的调用位置。
2. 读取当前源码文件，找出检查点后下一条代码行，并返回附近的代码片段。
3. 将步骤记录为 `paused`，等待 `asyncio.Event`。
4. 用户点击下一步，后端核对步骤序号后只释放当前 Event。
5. 程序执行到下一个检查点，再次等待新的 Event。

这里没有执行任意用户 Python 代码，也没有使用 `eval()`。代码片段来自仓库实际源文件；不读取或展示运行时局部变量、原文参数值或 API Key。Skill 原文通过受限的技能文件路径提供。

### 暂停范围

这是**关键步骤单步执行器**，不是逐条 Python 语句的完整 Debugger。一次放行执行到下一个检查点；一条 API 请求内部的 SDK 重试、协议库内部操作和 MCP Server 子进程内部语句不会逐行暂停。MCP 节点显示真实客户端调用行，并说明对应服务端入口 `mcp_server.py`，不会伪造服务端执行轨迹。

## 6. 调试接口

| 方法及路径 | 作用 |
|---|---|
| `POST /api/debug/start` | 校验请求并创建随机会话 ID，后台任务立即停在首个检查点 |
| `GET /api/debug/{id}` | 获取实际步骤、暂停/运行状态、已完成组合结果 |
| `POST /api/debug/{id}/next` | 提交 `{"seq": 当前步骤序号}`，只放行这一处 |
| `POST /api/debug/{id}/cancel` | 取消任务并清理正在使用的会话/子进程 |

创建请求与普通翻译相似，但使用 `pairs` 数组：

```json
{
  "text": "Hello!",
  "source": "en",
  "pairs": ["zh-en"],
  "model": "",
  "api_key": ""
}
```

调试时按组合顺序执行，便于学习；普通翻译继续并行请求选中组合。原有 `/api/compare` 和 CLI 均保留。

同一 `seq` 不能放行两次，双击也不会预存下一步许可。无效或过时步骤返回 409。错误记录保留在对应节点，某一组合失败可以继续其他选中组合。

## 7. 会话管理与边界

- 调试会话只保存在后端进程内存，不写文件或浏览器持久存储。
- 使用高熵随机 ID；知道 ID 才能读取和控制对应会话，应将 ID 当作本机会话凭据。
- 默认只监听本机；控制请求检查浏览器来源及 JSON 类型，不向页面回显原始错误或 API Key。
- 单次暂停最多 5 分钟，整次调试最多 20 分钟；超时需重新开始。
- 最多保留 16 个会话，15 分钟无步骤状态更新的会话会被清理；服务退出会取消所有活动任务。
- 关闭或刷新网页不会在浏览器卸载时可靠发送取消请求，后端暂停超时会终止任务；需要立即结束时请点击结束调试。
- 调试服务使用单个 Python 进程运行。不要开启多 worker，因为内存会话不跨进程共享。

- 取消和暂停超时后不执行待执行操作。
- 默认非调试调用立即执行。
- 显示的源代码与文件实际行号一致。
- 真实 MCP 子进程运行时仍按检查点暂停。
- 真实 OpenAI SDK 配合本地 HTTP 替身，验证模型请求、工具回传和第二次请求的门控。
- 请求 Key 不出现在步骤快照中；无效来源和请求被拒绝。

浏览器已实际验证免费模式从 Agent、Skill、Engine、MCP 到结果交付的九步流程；外部翻译请求使用公开示例 Hello!，最终得到“您好！”。同时验证了 Skill 原文展开、取消勾选后隐藏/停止、恢复普通翻译、桌面右侧布局及手机布局。浏览器未记录脚本错误。

没有使用线上 OpenAI Key 进行收费大模型翻译验收；模型路径使用真实 SDK、本地响应替身与真实 MCP 验证。
